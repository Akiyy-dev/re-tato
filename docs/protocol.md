# 协议范围

项目使用 Tatotalk layer 123 的已恢复业务结构，以及固定版本 Telethon 的底层 MTProto 握手、加密和 sender。不会用 TelegramClient 的用户 API 猜测兼容性。

连接使用标准 obfuscated abridged 传输，固定服务端 RSA 公钥指纹为 `2bad57ceedcd0248`。仓库中的 PEM 仅为服务器公钥，不是账号认证密钥或私人密钥。

`research/` 中发布的 TL 声明来自客户端静态结构核对，仅保留运行需要的声明，不包含安装样本、反汇编输出、网络采样或本机测试记录。部分旧版及自定义 constructor 使用本地描述性别名，必须使用声明中的显式 ID，不能由别名重新计算 CRC。

## 业务结构

- 邮箱认证、人工图形校验和授权身份前缀；授权 flags 只有 bit0 增加临时会话字段。
- 短更新、批量更新、普通与频道新消息、常用用户/会话及媒体结构。
- 全局 Difference、频道 Difference 和 Dialogs 分页基线；全局及每个频道分别保存 pts。
- 服务端系统消息、频道成员变更及常见元数据更新。

原始更新在 SDK 确认前同步加密持久化。未知 constructor 不猜长度、不跳字节；保留加密数据用于后续重放。事件、冻结载荷及同步候选使用 SQLite 事务，只有连续已处理前缀才能提升持久化进度。独立进度分量单调合并，避免后续快照覆盖频道或全局进度。

首轮基线完成后，新发现频道使用保守恢复起点；无法完整恢复的 TooLong 缺口保留并报告。单个频道的权限或恢复错误局部退避，不中断其他会话。

## 边界

尚未闭合所有特殊自定义媒体、网页即时预览 Page 和 DecryptedMessageAction。也不提供服务端 TooLong 后的完整历史重建、编辑/撤回导出或多账号管理。不要把有限 schema、合成测试或部分实测当作全消息类型覆盖证明。

外部 TL 解码具有输入、字符串、vector、深度及节点限制；RPC 和服务对象的 gzip 输入与展开输出各限制 1 MiB。底层方法的临时替换只在独占连接作用域内生效，退出时恢复原 descriptor。

登录会话、原始更新、正文、载荷、检查点及接入 Token 使用 Windows 当前用户 DPAPI 加密。诊断记录不输出验证码、Token、完整原始响应或账号密钥。
